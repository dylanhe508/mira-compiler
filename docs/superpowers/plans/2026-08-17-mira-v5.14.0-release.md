# Mira v5.14.0 Release Implementation Plan

> **For Codex:** Execute this plan sequentially in the current repository. Preserve all regression fixtures, use `apply_patch` for source changes/deletions, and verify before each completion claim.

**Goal:** Turn the current Mira tree into a clean v5.14.0 source release plus a Windows x86-64 binary release, while consolidating regression coverage and removing one-off test runners.

**Architecture:** Keep the compiler/runtime layout unchanged. Make the two platform trees report one version, move long-lived validation behind the existing `regress.sh` entry points, remove temporary runners without removing fixtures, then build release archives from an explicit staging directory under ignored `dist/`.

**Tooling:** C, GNU Make/MinGW, Bash, PowerShell archive/checksum commands, Git.

---

## Task 1: Establish the release manifest and script classification

**Files:**
- Create: `RELEASE_MANIFEST_v5.14.0.txt`
- Inspect: `win/tests/`, `linux/tests/`, `win/probe/`, `bench/`

1. Record the retained authoritative regression entry points: `win/regress.sh`, `linux/regress.sh`, and `bench/bench_regress.sh`.
2. Record deletion patterns for phase-specific runners and probes.
3. Record retained fixture classes (`*.mira`, test `*.c`, module trees, stdlib cases, fuzz/reference tools).
4. Verify every runner selected for deletion has no unique fixture embedded only inside the script; migrate any such essential input to a retained fixture first.
5. Commit the manifest separately.
