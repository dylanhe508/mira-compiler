# Mira v5.14.0 正式发布设计

## 目标

把当前已经完成类型增强、SSA/代码生成修复和显式产物输出的源码整理为可公开发布的 v5.14.0，同时保持仓库精简、发布物可验证，不冒充尚未完成的原生 Linux 验证。

## 发布范围

正式版本包含三类交付物：

1. `mira-compiler-v5.14.0-source.zip`：Windows/Linux 源码、标准库、构建文件、README、发布说明和保留的回归用例。
2. `mira-compiler-v5.14.0-windows-x86_64.zip`：Windows x86-64 编译器、运行时对象、标准库、README 和发布说明。
3. `SHA256SUMS.txt`：以上归档的 SHA-256。

Linux 源码进入正式版，但本机无法进行原生 Linux 运行验证，因此不发布 Linux 二进制。发布说明必须明确记录这一点。

## 版本与文档

- 将 Windows/Linux 编译器版本、REPL 版本和 README 统一为 `5.14.0`。
- 新增 `CHANGELOG.md`，记录 v5.14.0 的用户可见变化。
- 新增 `RELEASE_NOTES_v5.14.0.md`，说明亮点、兼容性、构建方法、验证范围和已知限制。
- README 的命令行章节以当前实际行为为准，覆盖 `--emit=ir`、`-S/--emit=asm`、`-c/--emit=obj` 与统一的 `-o`。
- 仓库当前没有许可证文件；本次不擅自选择许可证，也不在发布物中伪造授权声明。

## 测试资产整理

仓库只保留长期维护所需的正式回归入口和用例：

- 保留 `win/regress.sh`、`linux/regress.sh` 与 `bench/bench_regress.sh`。
- 保留所有仍用于正确性、诊断、模块、标准库、优化和代码生成回归的 `.mira`/`.c` 用例。
- 在删除阶段性 runner 前，把 v5.14.0 的关键覆盖并入正式回归入口，至少覆盖版本输出、CLI 产物模式、渐进类型、模块、标准库与代表性 O0-O3 执行结果。
- 删除 `win/tests/run_*.ps1`、`linux/tests/run_*.ps1`、`*.before-*.ps1`、`win/probe/` 下的临时探针脚本，以及 `bench31*`、`runall*`、`repro_o3*`、`rc_test*`、`mask_test*`、`summary*`、`bisect_msl*` 等阶段性调试/测量脚本。
- 删除 `win/fulltest.sh`，并移除 README 对它的公开说明；正式验证入口统一为回归脚本。
- 保留构建脚本、源码转换工具和 fuzz 用例生成/参考转换工具；它们不是一次性测试 runner。

## 发布验证

发布前从干净状态执行：

1. Windows 编译器与运行时完整构建。
2. Windows 正式回归入口通过。
3. Windows/Linux 平台中立源文件同步检查。
4. Linux 编译单元静态构建/语法验证；原生 Linux 执行标记为环境限制。
5. `mira -v` 和帮助文本核对。
6. 两个 ZIP 解压后检查目录结构、必需文件和无构建垃圾。
7. 对归档生成并复核 SHA-256。

## 仓库与发布边界

- 本任务只整理、提交并生成本地发布包。
- 不创建 Git 标签，不推送远端，不上传 GitHub Release。
- 发布包放入被 `.gitignore` 排除的 `dist/`，不把二进制或 ZIP 提交进源码历史。
- `SOURCE_COMMIT.txt` 在最终发布提交后更新为该提交的完整哈希，并在打包前验证。

## 完成标准

- 源码、README、帮助和 REPL 均报告 v5.14.0。
- 工作树只包含有意的发布整理提交，且无被跟踪的构建产物。
- 正式回归通过，关键覆盖没有因删除阶段性脚本而丢失。
- 源码包、Windows 包和校验文件可在 `dist/` 中直接用于 GitHub Release。
