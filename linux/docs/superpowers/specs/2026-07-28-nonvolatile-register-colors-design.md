# Mira 非易失寄存器颜色第一阶段设计

## 目标

在保持当前线性扫描分配器的前提下，将 Windows x64 非易失整数寄存器
R13、R14、R15、RBX、RDI、RSI、R12 加入 SSA 物理颜色集合，使跨调用存活值
优先驻留寄存器而不是强制 spill。

## 架构

物理颜色 0–4 保持现有易失寄存器映射；颜色 5–11 映射到七个非易失寄存器。
R10/R11 继续专用于 lowering 与 spill 临时值。线性扫描在普通值上仍优先使用易失颜色，
只有跨调用值必须选择 5–11；压力较高时普通值也可使用非易失颜色。

lowering 根据函数最终实际使用的非易失颜色生成保存/恢复。保存集合必须覆盖 SSA VReg
颜色和现有 fIR 快速变量寄存器，去重后在 prologue 保存、所有 RET 前逆序恢复。
spill frame 偏移和调用前 16 字节栈对齐必须包含保存区大小。

## 安全边界

- 仅实现颜色扩展、跨调用约束和 ABI 保存恢复，不接全局图着色。
- RSP/RBP/R10/R11 不作为普通颜色。
- SDIV/SREM 跨越区间仍禁止占用 RAX/RDX 对应颜色。
- 非易失寄存器仅在函数实际使用时保存。
- 所有正常返回路径恢复相同集合；调用点保持 Windows x64 shadow space 与 16 字节对齐。
- O0–O3 语义、递归、嵌套调用和 spill 行为必须保持正确。

## 验证

- 结构测试验证跨调用 interval 只能得到非易失颜色，普通小叶函数仍使用易失颜色。
- lowering 测试验证使用一个、奇数个和偶数个非易失颜色时的保存/恢复与栈对齐。
- Mira/C 差分覆盖跨调用累加、400 万次调用、递归和高寄存器压力。
- focused O0–O3、极端应用、长矩阵和预热编译耗时回归。
- 十行级预热编译中位数低于 100 ms；长矩阵相对同环境旧编译器不得回退超过 5%。
