# Mira Go 式并发与静态引用设计

## 目标

Mira 提供可多核运行的大量轻量任务、Channel 和 `select`。任务不与系统线程一一对应；固定工作线程复用轻量 Fiber。现有 `parallel/join` 保持兼容并接入新调度器。

## 语法

```mira
let ch = channel(16);

go [] {
    send(ch, 42);
};

let value = recv(ch);

select {
    recv(ch) as value: { print(value); }
    send(ch, 7):       { print(7); }
    default:           { print(0); }
}
```

基础接口包括 `go`、`channel(capacity)`、`send`、`recv`、`close`、`select`、`yield`、`join` 和等待全部任务。无缓冲 Channel 的容量为 0。

## 调度器

- 启动固定数量工作线程，默认等于逻辑处理器数，可通过运行时接口覆盖。
- 每个工作线程拥有本地就绪队列；全局注入队列接收外部提交。
- 未开始的任务可被其他工作线程窃取；已开始 Fiber 固定在创建它的工作线程，避免跨线程 Fiber/TLS 风险。
- Channel 阻塞时任务进入等待队列并切回调度 Fiber，不阻塞工作线程。
- `yield` 将当前任务放回本地队列尾部。
- 调度器记录活动任务数；等待全部任务以事件通知完成。
- panic/throw 状态按任务隔离，不跨工作线程跳转。

## Channel

- Channel 保存元素环形缓冲、关闭状态、发送等待队列和接收等待队列。
- 无缓冲发送与接收直接配对。
- 有缓冲发送优先交付等待接收者，否则写入缓冲；缓冲满时挂起。
- 接收优先消费缓冲，再配对等待发送者；关闭且耗尽时返回关闭状态。
- `close` 唤醒全部等待者；重复关闭产生确定性运行时错误。
- Channel 内部使用窄临界区；锁内不切换 Fiber、不执行用户代码。

## Select

- 解析器将每个 case 降级为运行时选择描述符。
- 运行时先随机化起点并扫描立即可执行 case，降低固定顺序饥饿。
- 没有可执行 case 且存在 `default` 时立即选择 default。
- 否则一次性登记等待关系；任一 Channel 成功认领后撤销其他登记并恢复任务。
- 认领使用原子状态，保证只执行一个 case。

## 静态引用

静态引用在任务和 Channel 边界建立并发事实：

- 被任务捕获的局部值标记为 `ESCAPED`。
- 只读、不可别名的捕获标记为并发只读，可零拷贝共享。
- 可变捕获若不能证明任务独占，则标记为 `SHARED`，禁止跨任务栈引用和不安全的标量替换。
- 发送到 Channel 的引用视为所有权转移候选；发送后源值无后续读取且接收端唯一时，保留 `UNIQUE`。
- 不能证明唯一转移时退化为共享并保留同步。
- `send/recv/close/select/go` 是显式并发效果；DCE、内联、代码移动和内存优化不得跨越未证明安全的并发效果。
- 智策使用静态引用摘要选择零拷贝传递、批量任务、Channel 快路径和保守回退。

证据不足时只关闭相关优化，不关闭并发功能。

## 验证

- 单工作线程验证调度顺序、挂起、恢复和关闭。
- 多工作线程验证任务只执行一次、工作窃取和等待全部任务。
- Channel 覆盖容量 0、1、N、满/空阻塞、多生产者、多消费者和关闭。
- `select` 覆盖立即就绪、default、多 case 竞争、撤销登记和公平性。
- 静态引用结构测试覆盖只读捕获、唯一转移、共享退化和并发效果屏障。
- 运行 10,000 个轻量任务，系统线程数保持在工作线程数量级。
- 现有 `parallel/join`、modern、结构体、SSA、寄存器和 fib 回归不得退化。
