# Mira 同块除余复用设计

## 目标

在不改变语言语义、不增加跨块数据流成本的前提下，让同一基本块内相同操作数的
`x / d` 与后续 `x % d` 只触发一次硬件有符号除法。

## 方案

优化仅在 O2/O3 且 `decision_plan.pipeline.allow_magic_division` 开启时运行。
扫描每个基本块中的 `SREM`，向前最多检查 128 条指令；若找到操作数种类和值均完全
相同的 `SDIV`，将余数改写为：

```text
product = quotient * divisor
remainder = dividend - product
```

匹配限制在同一基本块，因此商的定义天然支配新乘法和减法。SSA VReg 操作数不可被
重新定义；立即数直接按值匹配。BLOCK、符号或其他 operand kind 不参与匹配。

## 安全边界

- 不跨基本块、分支或调用寻找商。
- 只复用位于余数之前且 `dst != 0` 的有符号除法。
- 被除数、除数必须同时完全相同。
- 保持 C/Mira 有符号整数除法向零截断语义；恒等式
  `x % d == x - (x / d) * d` 对合法的非零除数成立。
- 不处理除数为零；原程序若执行该路径仍保持原有异常语义。
- 不增加专门识别 fib 或矩阵的硬编码。

## 测试

- 新增结构测试，证明 O1 不改写、O2/O3 将一个 `SREM` 改为 `MUL+SUB`。
- 覆盖 VReg/立即数操作数、不匹配除数、不匹配被除数、跨块不复用。
- 新增 Mira/C 差分程序，覆盖正数、负数、零与非相邻同块表达式。
- 运行现有 focused O0–O3、长矩阵和预热编译耗时。
- 十行级预热编译中位数必须低于 100 ms，长矩阵不得超过当前中位数 64.725 ms 的 5%。
